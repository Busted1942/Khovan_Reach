**Read `spawn_count`, not the map.** It is the reliable tell, and it distinguishes the two failure modes:

| Run 2 trace | Meaning |
|---|---|
| `[KHOVAN ACT2 HALCYON 002] Halcyon spawned id=<new> spawn_count=2` | Correct. |
| `[KHOVAN ACT2 HALCYON] reused existing contact id=<the run-1 id>` | **The race.** Cleanup's `delete_object` fires its destroy hook *deferred*, so the doomed object was still in the role index when spawn queried it. Spawn re-adopts it and returns early; the destroy hook then removes it. Result is **zero contacts**, with `halcyon_spawned = True` and a dead id — and the flag guard makes every later spawn a silent no-op, so re-running JUMP-013 never recovers. |
